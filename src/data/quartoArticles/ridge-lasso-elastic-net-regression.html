Background: What Linear Regression Actually Is

Before touching Ridge or Lasso, it helps to be clear on the base model they modify. Linear regression is one of the oldest tools in statistics and machine learning. Its job is simple to state. You have some input features, and you want to predict one continuous number.

A continuous number just means a value that can fall anywhere on a scale, not a fixed category. A stock’s forward return, a house’s price, and a company’s expected revenue are all continuous numbers. This is different from classification, where the goal is to predict a category, such as default or no default. That distinction matters, because Ridge, Lasso, and Elastic Net only apply to this regression setting.

Linear regression assumes a straight-line relationship between the inputs and the output. With one feature, this is literally a line on a graph.

y=θ0+θ1xy = \theta_0 + \theta_1 xy=θ0​+θ1​x

Breaking this down. y is the value you are trying to predict, the forward return in this article. x is your input feature, one day’s momentum reading. θ₀, theta-zero, is the intercept, the baseline value of y when x is zero. θ₁ is the slope, how much y changes for every one unit increase in x. With more than one feature, the same idea just adds more slope terms, one θ per feature, all added together.

Where it is used. Linear regression is the default starting point almost anywhere a business needs to predict a number from historical data. A bank uses it to estimate how a customer’s income and credit history relate to their expected loan balance. A retailer uses it to link advertising spend to sales. An asset manager uses it, as in this article, to link past price momentum to future returns. It is popular because it is fast to fit, easy to interpret, and the coefficients directly answer a business question. A coefficient of 0.6 on momentum tells you, in plain terms, how much forward return to expect per unit of momentum.

Why it usually is not enough on its own. Plain linear regression, fit with ordinary least squares, has one weak spot. It has no built-in way to handle features that overlap or duplicate each other, which is extremely common once you engineer more than a couple of features from real data. That weak spot is exactly what this article addresses next.

A linear regression model with five correlated momentum signals often fits a backtest beautifully. Then it falls apart on new data. This is not bad luck. It is a direct result of how ordinary least squares behaves when features overlap. This article covers the standard fix: penalizing a model for leaning too hard on any single feature. That family of techniques is called regularization.

We covered unsupervised pattern discovery in our clustering deep-dive. That article grouped data with no target variable at all. Regularized regression sits on the opposite side of machine learning. Here you have a specific number to predict, such as next month’s return or a default probability. The danger is not a lack of structure. The danger is a model that finds structure that is not really there.

The Problem: When More Features Make a Model Worse

Picture a quant desk building a momentum strategy on the SPY ETF. The idea is well documented in finance. Assets that performed well recently tend to keep performing well for a while. To capture this, the desk engineers five momentum features from one price series. Each feature measures annualized return over a different trailing window.

Feature Window What it captures
Ret10 10 trading days Very short-term momentum
Ret25 25 trading days Short-term momentum
Ret60 60 trading days Medium-term momentum
Ret120 120 trading days Medium-to-long momentum
Ret240 240 trading days Roughly one-year momentum

The target is the forward 25-day return, what actually happens next. This looks like a reasonable supervised regression setup. The catch is that all five features come from the same price series. They are just measured over overlapping windows. Strong 10-day momentum is very likely to also show up as strong 25-day and 60-day momentum. Ordinary least squares cannot tell which feature deserves the credit. It starts assigning wild, unstable coefficients. One lag gets a large positive weight. A neighboring lag gets a large negative weight that cancels it out on the training data. The in-sample fit looks excellent. The out-of-sample performance is closer to a coin flip.

This is the textbook case for regularization. A penalty keeps every coefficient honest. It discourages the model from leaning too hard on any single, possibly redundant, feature.

A Second Case: The Overfit Assignment Everyone Has Submitted

This exact trap shows up outside trading desks too. Say a student is asked to predict house prices for a class assignment. The dataset includes square footage, number of rooms, and lot size. It also includes total interior floor area, a near-duplicate of square footage. A plain linear regression fits the training set almost perfectly. On the held-out test set, the error jumps sharply. The grader’s comment is predictable. The model has memorized noise, not learned the real pricing pattern. Regularization is the standard, defensible fix to cite in that kind of report.

What Regularization Actually Does to the Cost Function

Ordinary least squares chooses coefficients θ to minimize prediction error. Formally, it minimizes mean squared error between predictions and actual outcomes. Regularization adds a second term to that objective. This new term penalizes the size of the coefficients themselves.

J(θ)=MSE(θ)+Penalty(θ)J(\theta) = \text{MSE}(\theta) + \text{Penalty}(\theta)J(θ)=MSE(θ)+Penalty(θ)

Breaking this down. J(θ) is the total cost the model tries to minimize. Think of it as a score where lower is better. θ, the Greek letter theta, stands for the coefficients the model is learning, one number per feature. MSE(θ) is the usual error term, how far off the predictions are from the real answers. Penalty(θ) is the new piece. It is a second score that grows whenever the coefficients get large. The model now has to balance two goals in one number.

The model now solves two problems at once. It fits the data well, and it keeps the coefficients small. This penalty is only active during training. Once the model is fit, you evaluate it using the plain, unregularized prediction error. The penalty’s only job is to shape the fitting process.

Three techniques define what “Penalty(θ)” actually looks like. They are Ridge, Lasso, and Elastic Net. Each makes a different trade-off. These differences are not cosmetic. They change which coefficients survive.

Ridge Regression (L2): Shrinking Everything Toward Zero

Ridge is also called Tikhonov regularization. It adds a penalty proportional to the square of each coefficient. According to scikit-learn’s documentation, this model solves a regression problem where the loss function is ordinary least squares, with regularization given by the L2 norm.

J(θ)=RSS(θ)+α∑i=1nθi2J(\theta) = \text{RSS}(\theta) + \alpha\sum_{i=1}^{n} \theta_i^2J(θ)=RSS(θ)+αi=1∑n​θi2​

Breaking this down. RSS(θ) is the residual sum of squares, the normal regression error before any penalty. The symbol α, alpha, is a single number you choose. It is the dial that sets how strict the penalty is. The Σ symbol means “add up.” It runs from i = 1 to n, where n is the number of features. So Σθᵢ² means “square every coefficient, then add all those squares together.” Multiplying that sum by α gives the penalty its final size. A bigger α means a bigger penalty, and smaller final coefficients.

Here RSS is the residual sum of squares. Alpha is a hyperparameter controlling how aggressively coefficients get pulled toward zero. This matches scikit-learn’s convention directly. The WQU course notes present an equivalent MSE-based version scaled by one half. That scaling only rescales alpha, not the underlying behavior. Regularization improves the conditioning of the problem and reduces the variance of the estimates. Larger alpha values mean stronger regularization. Push alpha to zero and you recover ordinary least squares exactly. Push it very high and every coefficient collapses toward zero.

Worked Example: Shrinking a Single Momentum Coefficient by Hand

Take a tiny, mean-centered toy version of the problem. Below are four days of 10-day momentum, x, and the forward 25-day return that followed, y. Both are in percent.

Day x (10-day momentum) y (forward 25-day return)
1 2.0 1.5
2 −1.0 −0.5
3 3.0 2.0
4 −2.0 −1.0

For a single-feature regression through the origin, the ordinary least squares solution is θ = Σxᵢyᵢ / Σxᵢ². Computing both sums:

Σx² = 2² + (−1)² + 3² + (−2)² = 4 + 1 + 9 + 4 = 18

Σxy = (2)(1.5) + (−1)(−0.5) + (3)(2.0) + (−2)(−1.0) = 3 + 0.5 + 6 + 2 = 11.5

OLS coefficient: θ = 11.5 / 18 ≈ 0.639

The closed-form ridge solution for a single feature is θ_ridge = Σxy / (Σx² + α). Applying two different penalty strengths:

α = 5: θ_ridge = 11.5 / (18 + 5) = 11.5 / 23 ≈ 0.500

α = 50: θ_ridge = 11.5 / (18 + 50) = 11.5 / 68 ≈ 0.169

The coefficient shrinks steadily. It never actually reaches zero, no matter how large alpha gets. It just gets vanishingly small. That is the defining behavior of Ridge. It dampens every coefficient, but it never removes one entirely.

What this means in practice. An OLS coefficient of 0.639 says every one percent of extra 10-day momentum predicts a 0.639 percent forward return. That number is inflated by the overlap with the other four momentum features. At α = 5, the honest, deflated estimate is closer to 0.500. At α = 50, the model is telling you it barely trusts this single feature at all, and is spreading the credit elsewhere. For a trading desk, this changes position sizing directly. A smaller, more honest coefficient means smaller, more honest bets. For a student writing up results, this number is the evidence that the model is no longer overreacting to one noisy signal. Drag the alpha slider yourself in the Shrinkage Duel tab of the simulator below. Watch this exact calculation update live.

For a full multi-feature dataset, gradient descent updates the parameter vector using:

θ[next]=θ[prev]−η ∇θMSE(θ[prev])−α⊙θ[prev]\theta^{[\text{next}]} = \theta^{[\text{prev}]} - \eta \, \nabla_\theta \text{MSE}(\theta^{[\text{prev}]}) - \alpha \odot \theta^{[\text{prev}]}θ[next]=θ[prev]−η∇θ​MSE(θ[prev])−α⊙θ[prev]

Breaking this down. This formula describes one small update step during training. θ[prev] is the current set of coefficients, before this step. θ[next] is the updated set, right after this step. η, eta, is the learning rate, how big a step the model takes each time. The symbol ∇θMSE means the gradient, the direction that would most increase the error. Subtracting it moves the coefficients toward less error instead. The final term, α times θ[prev], is the Ridge penalty pulling every coefficient a little closer to zero on each step. The ⊙ symbol just means this happens to each coefficient individually.

The penalty term excludes the bias, or intercept. Only the slope coefficients get regularized.

from sklearn.linear_model import Ridge
from sklearn.preprocessing import StandardScaler

# Standardizing is essential before Ridge. Without it, features on
# different scales get penalized unfairly. A coefficient on a feature
# measured in thousands looks "bigger" than one measured in decimals,
# purely due to units, not real importance.
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)

ridge = Ridge(alpha=5.0)
ridge.fit(X_train_scaled, y_train)

test_mse = ((ridge.predict(X_test_scaled) - y_test) ** 2).mean()

Lasso Regression (L1): Deleting Features Entirely

Lasso stands for Least Absolute Shrinkage and Selection Operator. It swaps the squared penalty for an absolute-value penalty.

J(θ)=RSS(θ)+α∑i=1n∣θi∣J(\theta) = \text{RSS}(\theta) + \alpha\sum_{i=1}^{n} |\theta_i|J(θ)=RSS(θ)+αi=1∑n​∣θi​∣

Breaking this down. This looks almost identical to the Ridge formula above. The only change is |θᵢ| instead of θᵢ². The vertical bars mean absolute value, the size of the number with the sign stripped off. So instead of squaring each coefficient, Lasso just adds up their plain sizes. That single swap is what allows coefficients to hit exactly zero, which the next section explains.

That small change in exponent has a large practical consequence. For a well-chosen alpha, Lasso can recover the exact set of relevant variables using only a few observations, under certain conditions. In other words, Lasso does not just shrink coefficients. It can drive them to exactly zero. This effectively deletes a feature from the model. Lasso is a built-in feature-selection tool, not just a stabilizer.

The term |θᵢ| is not differentiable at θᵢ = 0. Fitting Lasso requires a subgradient step:

θ[next]=θ[prev]−η ∇θMSE(θ[prev])−α⊙sign(θ[prev])\theta^{[\text{next}]} = \theta^{[\text{prev}]} - \eta \, \nabla_\theta \text{MSE}(\theta^{[\text{prev}]}) - \alpha \odot \text{sign}(\theta^{[\text{prev}]})θ[next]=θ[prev]−η∇θ​MSE(θ[prev])−α⊙sign(θ[prev])

Breaking this down. This is the same update pattern as Ridge, with one change. Instead of subtracting α times the coefficient itself, it subtracts α times sign(θ[prev]). The sign function just returns whether a coefficient is positive, negative, or zero, as +1, −1, or 0. So every coefficient gets pushed toward zero by the same fixed amount each step, regardless of how large it is. That fixed push, rather than a proportional one, is why Lasso can reach exactly zero.

Most implementations solve this with coordinate descent instead. This updates one coefficient at a time using a closed-form soft-thresholding rule:

θj=S(ρj,α)∑ixij2,S(z,γ)=sign(z)⋅max⁡(∣z∣−γ,0)\theta_j = \frac{S(\rho_j, \alpha)}{\sum_i x_{ij}^2}, \qquad S(z, \gamma) = \text{sign}(z) \cdot \max(|z| - \gamma, 0)θj​=∑i​xij2​S(ρj​,α)​,S(z,γ)=sign(z)⋅max(∣z∣−γ,0)

Breaking this down. θⱼ is one single coefficient, updated on its own. ρⱼ, rho, is a running correlation between feature j and the current prediction errors. Think of it as the raw, unpenalized signal for that one feature, similar to Σxy in the worked example below. The denominator, Σxᵢⱼ², is just that feature’s own sum of squares. The function S is soft-thresholding. It takes a value z and a threshold γ, gamma. If |z| is smaller than γ, S returns exactly zero. Otherwise it shrinks z toward zero by γ and keeps its original sign. This is the mechanical reason Lasso deletes small, weak features entirely.

Worked Example: Watching a Coefficient Hit Exactly Zero

Reuse the same four-day toy dataset, where Σx² = 18 and Σxy = 11.5. The single-feature Lasso solution is θ_lasso = S(Σxy, α) / Σx².

α = 5: S(11.5, 5) = 11.5 − 5 = 6.5 → θ_lasso = 6.5 / 18 ≈ 0.361

α = 11.5 (the exact breaking point): S(11.5, 11.5) = 0 → θ_lasso = 0.000

At α = 11.5, the penalty exactly cancels the signal. The coefficient snaps to zero. This feature has just been deleted from the model. Push alpha any higher and it stays at zero. This is a moment Ridge can never produce. No matter how large Ridge’s alpha gets, its coefficient only approaches zero. Lasso reaches zero outright. The exact threshold is |Σxy|, in this simplified single-feature case.

What this means in practice. For the momentum desk, a coefficient of exactly zero at α = 11.5 is a concrete, actionable signal. It says the 10-day lag adds nothing once the other four windows are in the model. The desk can drop that data feed entirely and simplify the pipeline. For a school project on, say, predicting loan default from twenty applicant features, this is the number you report as evidence of feature selection. You can write, in your methodology section, that Lasso zeroed out a named list of coefficients at the chosen alpha, and that this matches domain intuition about which variables should matter. Try this in the Shrinkage Duel tab below. Push the alpha slider past the marked threshold. Watch the Lasso bar disappear while the Ridge bar keeps shrinking.

If alpha is chosen too small, irrelevant variables stay in the model. If alpha is chosen too large, Lasso behaves like simple stepwise regression, discarding too much. The real skill in using Lasso is landing in the middle range. You want enough penalty to drop redundant features. You do not want so much that it discards real signal.

from sklearn.linear_model import Lasso

lasso = Lasso(alpha=0.05)
lasso.fit(X_train_scaled, y_train)

# Inspect which momentum lags survived
surviving_features = [
    name for name, coef in zip(feature_names, lasso.coef_) if coef != 0
]
print(surviving_features)

Elastic Net: Getting the Best of Both

Elastic Net runs both penalties in the same optimization. A mixing parameter r controls the balance.

J(θ)=RSS(θ)+rα∑i=1n∣θi∣+1−r2α∑i=1nθi2J(\theta) = \text{RSS}(\theta) + r\alpha\sum_{i=1}^{n} |\theta_i| + \frac{1-r}{2}\alpha\sum_{i=1}^{n} \theta_i^2J(θ)=RSS(θ)+rαi=1∑n​∣θi​∣+21−r​αi=1∑n​θi2​

Breaking this down. This formula just glues the Lasso penalty and the Ridge penalty together. r is a number between 0 and 1 that decides how much weight each penalty gets. The middle term, rα times the sum of |θᵢ|, is the Lasso half, scaled down by r. The last term, using (1−r)/2 times α, is the Ridge half, scaled by whatever is left over. When r is close to 1, the Lasso term dominates. When r is close to 0, the Ridge term dominates.

When r equals 1, this collapses to pure Lasso. When r equals 0, it collapses to pure Ridge. Anywhere in between, it blends two strengths. It inherits Lasso’s ability to zero out features. It inherits Ridge’s stability when features are highly correlated. That stability matters, because plain Lasso has a real weakness. It tends to arbitrarily pick one feature from a correlated group and drop the rest.

Worked Example: Combining Both Penalties

Using the coordinate-descent form of Elastic Net, the single-feature update is:

θEN=S(Σxy, rα)Σx2+(1−r)α\theta_{EN} = \frac{S(\Sigma xy,\ r\alpha)}{\Sigma x^2 + (1-r)\alpha}θEN​=Σx2+(1−r)αS(Σxy, rα)​

Breaking this down. The top of the fraction runs the same soft-thresholding function S from the Lasso section. It uses rα as the threshold, the Lasso share of the penalty. The bottom of the fraction is the usual Σx² term, but with (1−r)α added to it, the Ridge share of the penalty. So the numerator handles feature deletion, and the denominator handles shrinkage, both in one formula.

Set r = 0.5 and α = 10 on the same toy dataset. Then rα = 5 and (1−r)α = 5.

θEN=S(11.5, 5)18+5=6.523≈0.283\theta_{EN} = \frac{S(11.5,\ 5)}{18 + 5} = \frac{6.5}{23} \approx 0.283θEN​=18+5S(11.5, 5)​=236.5​≈0.283

Notice both effects at once. The L1 term trimmed the numerator, exactly as Lasso would. The L2 term inflated the denominator, exactly as Ridge would. This is a genuine blend, not an average of the two standalone results.

What this means in practice. Suppose the momentum desk later adds two more overlapping features, a 15-day and a 20-day window, sitting right between the existing lags. Plain Lasso would likely keep one of these near-duplicates and zero out the rest at random. That is unstable behavior a risk committee will not like, since a tiny data revision could flip which lag survives. Elastic Net tends to keep or drop correlated groups together instead, which is far easier to explain and defend in a model review. This is also the safer default for a school assignment with many engineered features, since it avoids the appearance of an arbitrary, unstable selection.

from sklearn.linear_model import ElasticNet

elastic_net = ElasticNet(alpha=0.05, l1_ratio=0.5)  # l1_ratio is r
elastic_net.fit(X_train_scaled, y_train)

Hyperparameter Tuning: Finding the Right α (and r) With Cross-Validation

Every regularized model adds at least one new dial to turn. Ridge and Lasso need alpha. Elastic Net needs alpha and r as well. Picking these from a single train and test split is unreliable. A single split’s performance is noisy. The standard fix is k-fold cross-validation. You split the training data into k roughly equal folds. Train on k minus one of them, and validate on the one held out. Rotate which fold is held out until each has served once. The final cross-validation score is the average error across all rotations.

CV(α)=1k∑f=1kMSEf(α)\text{CV}(\alpha) = \frac{1}{k}\sum_{f=1}^{k} \text{MSE}_f(\alpha)CV(α)=k1​f=1∑k​MSEf​(α)

Breaking this down. k is the number of folds you split the data into, five in the example below. MSEf(α) is the error you get on fold f, using a given alpha value. The Σ symbol adds up that error across all k folds. Dividing by k at the front turns that total into a plain average. CV(α) is simply the average validation error for one candidate alpha value, which you then compare against other candidates.

Worked Example: Choosing Between Two α Values

Suppose the momentum dataset above is split into k = 5 folds. We compare α = 1 against α = 10, recording validation MSE on each fold.

Fold MSE at α = 1 MSE at α = 10
1 0.185 0.171
2 0.201 0.179
3 0.179 0.183
4 0.211 0.174
5 0.193 0.168

CV(α=1) = (0.185+0.201+0.179+0.211+0.193) / 5 = 0.969 / 5 = 0.194

CV(α=10) = (0.171+0.179+0.183+0.174+0.168) / 5 = 0.875 / 5 = 0.175

Alpha equal to 10 wins on average. Its fold-by-fold scores are also tighter together. That tighter spread signals a model that is more stable across different slices of the data.

What this means in practice. A 0.019 drop in average MSE looks small on paper, but scale matters here. On a forward 25-day return series, that gap can be the difference between a strategy that survives transaction costs and one that does not. The tighter spread across folds at α = 10 also matters on its own. A model whose error swings wildly between folds is a model that got lucky on some slices of history and unlucky on others. For a class report, this is the exact number and reasoning to cite when justifying a chosen alpha instead of just picking a default value.

A single k-fold split is itself somewhat random. It is common to repeat the whole process with different random splits. You then average across all of them. This is called repeated k-fold cross-validation. Scikit-learn’s RepeatedKFold automates exactly this.

GridSearchCV vs. RandomizedSearchCV

GridSearchCV tests every combination of hyperparameter values you specify. Each combination gets evaluated with cross-validation. This is thorough, but combinations explode as you add hyperparameters. RandomizedSearchCV instead samples a fixed number of random combinations. It scales far better once you tune more than one or two hyperparameters at once. The trade-off is that it no longer tests every combination.

from sklearn.linear_model import ElasticNet
from sklearn.model_selection import GridSearchCV, RepeatedKFold

cv_strategy = RepeatedKFold(n_splits=10, n_repeats=3, random_state=1)

param_grid = {
    "alpha": [1e-4, 1e-3, 1e-2, 1e-1, 1.0, 10.0],
    "l1_ratio": [0.0, 0.1, 0.3, 0.5, 0.7, 1.0],
}

search = GridSearchCV(
    ElasticNet(),
    param_grid,
    scoring="neg_mean_squared_error",
    cv=cv_strategy,
    n_jobs=-1,
)
search.fit(X_train_scaled, y_train)

print(search.best_params_)

Conclusion: Choosing the Right Penalty for Your Own Data

Ridge, Lasso, and Elastic Net all solve the same underlying problem. They stop a linear model from overreacting to noisy or overlapping features. Ridge is the safe default when most features carry some real signal. Lasso is the right tool when you suspect only a handful of features actually matter. Elastic Net is the balanced choice when features are correlated and you are not certain which case applies.

None of these choices should be made by guessing. Use cross-validation to compare candidate alpha values on your own data, the same way the worked example above compared α = 1 against α = 10. Report the winning value and the fold-by-fold spread, not just a single test-set score.

The momentum example here used five overlapping trading windows. The same logic applies directly to a credit scoring model with correlated financial ratios, or a class assignment with many engineered features from one raw dataset. Wherever features overlap, regularization is the first tool worth reaching for, before adding complexity elsewhere.

Regression assumes a straight-line relationship between features and a continuous target. Many finance problems instead ask for a category, such as whether a loan defaults or not.
