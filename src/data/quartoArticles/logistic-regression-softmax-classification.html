What Classification Is, and Why Regression Cannot Do It Alone

In our Ridge, Lasso and Elastic Net article, the model predicted a continuous number, a forward return. Many real business questions are not that shape at all. A bank does not usually ask for a customer’s exact future balance. It asks a simpler question. Will this customer default, yes or no. A trading desk does not always need the exact next return. It often just needs to know whether the market will go up or down.

This is a classification problem. The target is a category, not a number on a scale. The simplest case has only two categories, called binary classification. Will the market go up, y equals 1, or down, y equals 0. Will the loan default, y equals 1, or not, y equals 0. Linear regression can technically be forced to output a 0 or 1 label, but it does a poor job of it. Its output can run below 0 or above 1, which makes no sense as a probability. Logistic regression exists to fix exactly that.

Logistic Regression: Turning a Score Into a Probability

Logistic regression is the standard first tool for binary classification. It does not predict the label directly. It predicts the probability that an instance belongs to the positive class, then applies a threshold, usually 50 percent, to turn that probability into a decision.

The model first computes a score, the same weighted sum of features used in linear regression. It then passes that score through the sigmoid function.

p^(i)=σ(x(i)θ)=11+exp⁡(−x(i)θ)\hat{p}^{(i)} = \sigma\left(x^{(i)}\theta\right) = \frac{1}{1 + \exp\left(-x^{(i)}\theta\right)}p^​(i)=σ(x(i)θ)=1+exp(−x(i)θ)1​

Breaking this down. x(i)x^{(i)}x(i) is the feature vector for one instance, one row of input data. θ\thetaθ is the same coefficient vector from linear regression, one weight per feature, plus a bias term. x(i)θx^{(i)}\thetax(i)θ is the raw score, a weighted sum, exactly as in ordinary regression. This score can be any real number, negative or positive, large or small. The sigmoid function, written σ\sigmaσ, squashes that unbounded score into a value strictly between 0 and 1. That squashed value, p^\hat{p}p^​, is the model’s estimated probability that this instance belongs to the positive class.

Why sigmoid specifically. The sigmoid curve is shaped like a flattened S. Very negative scores map close to 0. Very positive scores map close to 1. A score of exactly 0 maps to exactly 0.5. This shape means the model becomes more confident as the raw score moves further from zero in either direction, which matches how a probability should behave.

Worked Example: Scoring a Single Trading Day by Hand

Suppose a simple one-feature model uses only 10-day momentum, xxx, to predict whether the market rises over the next 25 days. Training has produced a bias of θ0=−0.2\theta_0 = -0.2θ0​=−0.2 and a slope of θ1=0.9\theta_1 = 0.9θ1​=0.9 on standardized momentum.

p^=11+exp⁡(−1.06)=11+0.3465=11.3465≈0.743\hat{p} = \frac{1}{1 + \exp(-1.06)} = \frac{1}{1 + 0.3465} = \frac{1}{1.3465} \approx \mathbf{0.743}p^​=1+exp(−1.06)1​=1+0.34651​=1.34651​≈0.743

What this means in practice. The model estimates a 74.3 percent chance the market rises over the next 25 days, given this level of momentum. Since 0.743 is above the 0.5 threshold, the model predicts y^=1\hat{y} = 1y^​=1, market up. A trading desk could use this probability directly to size a position, rather than only using the binary decision. A 74.3 percent estimate justifies a larger long position than a 51 percent estimate would, even though both cross the same threshold.

Now compare a weaker momentum day, x=−0.5x = -0.5x=−0.5.

xθ=−0.2+(0.9)(−0.5)=−0.2−0.45=−0.65x\theta = -0.2 + (0.9)(-0.5) = -0.2 - 0.45 = \mathbf{-0.65}xθ=−0.2+(0.9)(−0.5)=−0.2−0.45=−0.65

p^=11+exp⁡(0.65)=11+1.9155≈0.343\hat{p} = \frac{1}{1 + \exp(0.65)} = \frac{1}{1 + 1.9155} \approx \mathbf{0.343}p^​=1+exp(0.65)1​=1+1.91551​≈0.343

This falls below 0.5, so the model predicts y^=0\hat{y} = 0y^​=0, market down. Notice the score and the probability moved in the same direction. A negative score always gives a probability below 0.5, and a positive score always gives a probability above 0.5.

Training the Model: The Log-Loss Cost Function

Linear regression is trained by minimizing squared error. Logistic regression needs a different cost function, because squared error does not punish confident, wrong probability estimates harshly enough. The standard choice is log loss, also called binary cross-entropy.

J(θ)=−1m∑i=1m[y(i)log⁡(p^(i))+(1−y(i))log⁡(1−p^(i))]J(\theta) = -\frac{1}{m}\sum_{i=1}^{m}\left[y^{(i)}\log\left(\hat{p}^{(i)}\right) + \left(1 - y^{(i)}\right)\log\left(1 - \hat{p}^{(i)}\right)\right]J(θ)=−m1​i=1∑m​[y(i)log(p^​(i))+(1−y(i))log(1−p^​(i))]

Breaking this down. mmm is the number of training examples. y(i)y^{(i)}y(i) is the true label for example iii, either 0 or 1. p^(i)\hat{p}^{(i)}p^​(i) is the model’s predicted probability for that example. Only one of the two terms inside the brackets is ever active for a given example. If y(i)=1y^{(i)} = 1y(i)=1, the second term becomes zero, and the formula only scores log⁡(p^(i))\log(\hat{p}^{(i)})log(p^​(i)). If y(i)=0y^{(i)} = 0y(i)=0, the first term becomes zero, and the formula only scores log⁡(1−p^(i))\log(1 - \hat{p}^{(i)})log(1−p^​(i)). The minus sign and the 1m\frac{1}{m}m1​ at the front turn this into a positive average cost that training tries to minimize.

Why logs, and why this punishes confidence. Log of a number close to 1 is close to 0, almost no penalty. Log of a number close to 0 is a large negative number, which becomes a large penalty once the minus sign is applied. So a confident, correct prediction, such as p^=0.95\hat{p} = 0.95p^​=0.95 for a true positive, gets almost no penalty. A confident, wrong prediction, such as p^=0.05\hat{p} = 0.05p^​=0.05 for a true positive, gets a very large penalty. This is exactly the behavior you want from a probability-based classifier.

Worked Example: Comparing Two Predictions by Hand

Take two training examples, both with true label y=1y = 1y=1, market actually went up.

Example A predicted p^=0.9\hat{p} = 0.9p^​=0.9, a confident and correct estimate.

CostA=−log⁡(0.9)≈0.105\text{Cost}_A = -\log(0.9) \approx \mathbf{0.105}CostA​=−log(0.9)≈0.105

Example B predicted p^=0.2\hat{p} = 0.2p^​=0.2, a confident but wrong estimate.

CostB=−log⁡(0.2)≈1.609\text{Cost}_B = -\log(0.2) \approx \mathbf{1.609}CostB​=−log(0.2)≈1.609

What this means in practice. Example B costs roughly fifteen times more than Example A, even though both are single, similarly sized mistakes in a loose sense. This is the mechanism that makes log loss a much better training signal than squared error for classification. It aggressively punishes a model that is both wrong and overconfident, which is the exact failure mode a bank or a trading desk cannot afford in a risk model.

There is no closed-form solution for the θ\thetaθ that minimizes this cost function. Gradient descent finds it instead, using the following gradient.

∂∂θjJ(θ)=1m∑i=1m[σ(x(i)θ)−y(i)]xj(i)\frac{\partial}{\partial\theta_j}J(\theta) = \frac{1}{m}\sum_{i=1}^{m}\left[\sigma\left(x^{(i)}\theta\right) - y^{(i)}\right]x_j^{(i)}∂θj​∂​J(θ)=m1​i=1∑m​[σ(x(i)θ)−y(i)]xj(i)​

Breaking this down. This formula looks almost identical to the gradient used for linear regression in our Ridge and Lasso article. The difference is that the prediction here is σ(x(i)θ)\sigma(x^{(i)}\theta)σ(x(i)θ), the sigmoid output, rather than a raw linear score. The bracketed term is simply the prediction error for example iii, predicted probability minus actual label. Multiplying by xj(i)x_j^{(i)}xj(i)​ and averaging over all examples gives the direction that most reduces log loss for coefficient jjj. This gradient can be regularized with the same Ridge or Lasso penalties covered in the previous article, since the underlying update mechanics are identical.

Deriving the Gradient, Step by Step

The gradient above is not handed down by assumption. It falls out of the chain rule, and it is worth deriving once so the formula stops looking arbitrary.

Start with the sigmoid function’s own derivative, since every later step depends on it.

σ(z)=11+exp⁡(−z)⇒dσdz=σ(z)(1−σ(z))\sigma(z) = \frac{1}{1+\exp(-z)} \quad \Rightarrow \quad \frac{d\sigma}{dz} = \sigma(z)\big(1-\sigma(z)\big)σ(z)=1+exp(−z)1​⇒dzdσ​=σ(z)(1−σ(z))

This is a standard result from the quotient rule, but the useful part is what it means. The sigmoid’s own slope is largest near z=0z = 0z=0, where σ(z)=0.5\sigma(z) = 0.5σ(z)=0.5, and flattens out toward the extremes, matching the S-shape described earlier.

Now consider the cost contributed by a single training example iii, writing p=σ(z)p = \sigma(z)p=σ(z) and z=x(i)θz = x^{(i)}\thetaz=x(i)θ to keep the notation compact.

ℓ(i)=y(i)log⁡(p)+(1−y(i))log⁡(1−p)\ell^{(i)} = y^{(i)}\log(p) + \left(1-y^{(i)}\right)\log(1-p)ℓ(i)=y(i)log(p)+(1−y(i))log(1−p)

Differentiate this with respect to ppp first, using the ordinary derivative of a logarithm.

∂ℓ(i)∂p=y(i)p−1−y(i)1−p\frac{\partial \ell^{(i)}}{\partial p} = \frac{y^{(i)}}{p} - \frac{1-y^{(i)}}{1-p}∂p∂ℓ(i)​=py(i)​−1−p1−y(i)​

Now apply the chain rule twice, once from ℓ(i)\ell^{(i)}ℓ(i) to ppp, and once from ppp to θj\theta_jθj​, using ∂p∂z=p(1−p)\frac{\partial p}{\partial z} = p(1-p)∂z∂p​=p(1−p) and ∂z∂θj=xj(i)\frac{\partial z}{\partial \theta_j} = x_j^{(i)}∂θj​∂z​=xj(i)​.

∂ℓ(i)∂θj=[y(i)p−1−y(i)1−p]⋅p(1−p)⋅xj(i)\frac{\partial \ell^{(i)}}{\partial \theta_j} = \left[\frac{y^{(i)}}{p} - \frac{1-y^{(i)}}{1-p}\right] \cdot p(1-p) \cdot x_j^{(i)}∂θj​∂ℓ(i)​=[py(i)​−1−p1−y(i)​]⋅p(1−p)⋅xj(i)​

Multiply the bracketed term through by p(1−p)p(1-p)p(1−p) directly. This is the step where the algebra collapses to something much simpler.

[y(i)p−1−y(i)1−p]p(1−p)=y(i)(1−p)−(1−y(i))p\left[\frac{y^{(i)}}{p} - \frac{1-y^{(i)}}{1-p}\right] p(1-p) = y^{(i)}(1-p) - \left(1-y^{(i)}\right)p[py(i)​−1−p1−y(i)​]p(1−p)=y(i)(1−p)−(1−y(i))p

Expand the right-hand side and collect terms.

y(i)(1−p)−(1−y(i))p=y(i)−y(i)p−p+y(i)p=y(i)−py^{(i)}(1-p) - \left(1-y^{(i)}\right)p = y^{(i)} - y^{(i)}p - p + y^{(i)}p = y^{(i)} - py(i)(1−p)−(1−y(i))p=y(i)−y(i)p−p+y(i)p=y(i)−p

Every ppp term with a y(i)y^{(i)}y(i) coefficient cancels exactly. What survives is simply y(i)−py^{(i)} - py(i)−p, so:

∂ℓ(i)∂θj=(y(i)−p)xj(i)=−[σ(x(i)θ)−y(i)]xj(i)\frac{\partial \ell^{(i)}}{\partial \theta_j} = \left(y^{(i)} - p\right)x_j^{(i)} = -\left[\sigma\left(x^{(i)}\theta\right) - y^{(i)}\right]x_j^{(i)}∂θj​∂ℓ(i)​=(y(i)−p)xj(i)​=−[σ(x(i)θ)−y(i)]xj(i)​

Sum this over all mmm examples, divide by mmm, and apply the overall minus sign from J(θ)=−1m∑iℓ(i)J(\theta) = -\frac{1}{m}\sum_i \ell^{(i)}J(θ)=−m1​∑i​ℓ(i), and the two negative signs cancel, leaving exactly the gradient stated above. The reason logistic regression is tractable at all is this cancellation. The messy sigmoid derivative, p(1−p)p(1-p)p(1−p), disappears completely, leaving a clean prediction-error term identical in shape to the linear regression gradient. This is not a coincidence. It is a direct consequence of pairing the sigmoid function with the log-loss cost function specifically, rather than any other combination of activation and cost.

A Real Business Case: Credit Default Prediction

Logistic regression is a foundational tool for credit risk, not just an academic example. A study published in Royal Society Open Science applied logistic regression alongside support vector machines and deep neural networks to peer-to-peer lending data, using it to replicate lender acceptance decisions and predict the likelihood of loan default. A separate peer-reviewed study applied a logistic regression model directly to consumer loan data from a Portuguese bank. It found that default risk rose with loan spread, loan term, and borrower age, while owning more credit cards was linked to lower default risk. That same study reported the model correctly predicted default outcomes in close to 90 percent of cases.

Picture a small lender building its own version of this model. It has loan spread, loan term, borrower age, and number of open credit cards as features, and a binary label, defaulted or not. The workflow is identical to the momentum example above. Standardize the features, fit logistic regression, then read the sigmoid output as a probability of default for each new applicant. The lender can then set its own approval threshold based on how much default risk it can absorb, rather than relying only on a fixed 50 percent cutoff.

A School Assignment Angle

A common class assignment mirrors this exactly. Given a small labeled dataset, such as hours studied and a pass or fail outcome, students are asked to fit a logistic regression model and report the estimated coefficient. That coefficient answers a direct question. How much does one extra hour of study shift the log-odds of passing. Reporting the sigmoid-transformed probability for a specific student, alongside the raw coefficient, is usually what separates a strong writeup from a weak one, since it shows the model’s output in a form a non-technical reader can actually understand.

Feature Scaling: A Step That Comes Before Any of This

Before fitting a logistic regression model, features generally need to be put on a comparable scale. Machine learning algorithms perform badly when input features have very different scales, since this slows down and worsens optimization methods such as gradient descent. Two common approaches handle this.

Min-max scaling, or normalization, shifts and rescales every value so it falls between 0 and 1.

xscaled(i)=xj(i)−min⁡jmax⁡j−min⁡jx^{(i)}_{\text{scaled}} = \frac{x^{(i)}_j - \min_j}{\max_j - \min_j}xscaled(i)​=maxj​−minj​xj(i)​−minj​​

Breaking this down. min⁡j\min_jminj​ and max⁡j\max_jmaxj​ are the smallest and largest values feature jjj takes across the training set. Subtracting the minimum shifts the smallest value to 0. Dividing by the range compresses everything into the 0 to 1 band.

Standardization instead subtracts the mean and divides by the standard deviation, giving the feature a distribution centered at 0 with unit variance. It does not force values into a fixed range, which can be a problem for some algorithms, but it is the more common default for logistic regression.

One detail matters more than which method you pick. Only the training set’s minimum, maximum, mean, or variance should be measured. Those same numbers are then applied to the validation and test sets. Measuring scaling statistics on the full dataset, tests included, leaks information from data the model is not supposed to have seen yet.

Softmax Regression: Classification With More Than Two Categories

Logistic regression handles two classes. Many real problems have more. A credit rating is not just default or no default. It can be AAA, BBB, or junk. Softmax regression, also called multinomial logistic regression, generalizes the binary classifier to this multi-class setting.

Instead of one coefficient vector θ\thetaθ, softmax regression learns a separate vector θ(c)\theta^{(c)}θ(c) for every category ccc. Each category gets its own score, and the softmax function turns all the scores into probabilities that sum to exactly 1.

p^c(i)=Softmaxc(x(i),Θ)=exp⁡(x(i)θ(c))∑j=1Cexp⁡(x(i)θ(j))\hat{p}_c^{(i)} = \text{Softmax}_c\left(x^{(i)}, \Theta\right) = \frac{\exp\left(x^{(i)}\theta^{(c)}\right)}{\sum_{j=1}^{C}\exp\left(x^{(i)}\theta^{(j)}\right)}p^​c(i)​=Softmaxc​(x(i),Θ)=∑j=1C​exp(x(i)θ(j))exp(x(i)θ(c))​

Breaking this down. CCC is the total number of categories, three in the credit rating example. Θ\ThetaΘ, capital theta, collects every category’s coefficient vector into one object. The numerator exponentiates the score for category ccc specifically. The denominator adds up the exponentiated scores across every category. Dividing the two turns category ccc’s raw score into a proper probability, guaranteed to land between 0 and 1, with all CCC probabilities summing to 1. The predicted category is simply whichever ccc has the highest score, and therefore the highest probability.

Worked Example: Rating a Company by Hand

Suppose a simplified credit model produces three raw scores for one company, one score per rating tier.

x(i)θ(AAA)=2.0,x(i)θ(BBB)=1.0,x(i)θ(junk)=0.1x^{(i)}\theta^{(\text{AAA})} = 2.0, \qquad x^{(i)}\theta^{(\text{BBB})} = 1.0, \qquad x^{(i)}\theta^{(\text{junk})} = 0.1x(i)θ(AAA)=2.0,x(i)θ(BBB)=1.0,x(i)θ(junk)=0.1

First exponentiate each score.

exp⁡(2.0)≈7.389,exp⁡(1.0)≈2.718,exp⁡(0.1)≈1.105\exp(2.0) \approx 7.389, \qquad \exp(1.0) \approx 2.718, \qquad \exp(0.1) \approx 1.105exp(2.0)≈7.389,exp(1.0)≈2.718,exp(0.1)≈1.105

Sum=7.389+2.718+1.105=11.212\text{Sum} = 7.389 + 2.718 + 1.105 = \mathbf{11.212}Sum=7.389+2.718+1.105=11.212

p^AAA=7.38911.212≈0.659,p^BBB=2.71811.212≈0.242,p^junk=1.10511.212≈0.099\hat{p}_{AAA} = \frac{7.389}{11.212} \approx \mathbf{0.659}, \qquad \hat{p}_{BBB} = \frac{2.718}{11.212} \approx \mathbf{0.242}, \qquad \hat{p}_{junk} = \frac{1.105}{11.212} \approx \mathbf{0.099}p^​AAA​=11.2127.389​≈0.659,p^​BBB​=11.2122.718​≈0.242,p^​junk​=11.2121.105​≈0.099

What this means in practice. The model assigns this company a 65.9 percent chance of an AAA rating, 24.2 percent BBB, and 9.9 percent junk. Since AAA has the highest probability, that is the predicted rating. Notice the three probabilities sum to exactly 1.0, a property plain logistic regression does not guarantee across multiple independent binary models. This is precisely the multi-class extension a peer-reviewed study in the International Journal of Fuzzy Systems used for sovereign credit ratings. That study applied a multinomial logistic model to a dataset of sovereign credit ratings across 61 countries, spanning 1995 to 2022. It is also the mechanism behind more advanced credit scoring research, where one recent study built a partially interpretable adaptive softmax regression model, combining softmax regression with a neural network to score borrower credit risk.

Training Softmax Regression: The Cross-Entropy Cost Function

Binary logistic regression is trained with log loss. Softmax regression is trained with its direct generalization, categorical cross-entropy. The target label is first written as a one-hot vector, yc(i)=1y_c^{(i)} = 1yc(i)​=1 if example iii truly belongs to class ccc, and yc(i)=0y_c^{(i)} = 0yc(i)​=0 for every other class.

J(Θ)=−1m∑i=1m∑c=1Cyc(i)log⁡(p^c(i))J(\Theta) = -\frac{1}{m}\sum_{i=1}^{m}\sum_{c=1}^{C} y_c^{(i)} \log\left(\hat{p}_c^{(i)}\right)J(Θ)=−m1​i=1∑m​c=1∑C​yc(i)​log(p^​c(i)​)

Breaking this down. For each example iii, exactly one term in the inner sum survives, the one where ccc matches the true class, because every other yc(i)y_c^{(i)}yc(i)​ is 0 and kills its term. So this collapses, per example, to −log⁡(p^true class(i))-\log(\hat{p}_{\text{true class}}^{(i)})−log(p^​true class(i)​), the negative log of the probability the model assigned to the correct answer. Averaging that over all mmm examples gives J(Θ)J(\Theta)J(Θ). This is exactly the same intuition as binary log loss, just written to handle more than two classes at once: a model that puts high probability on the correct class is cheap, a model that puts low probability on the correct class is expensive, and the penalty grows without bound as that probability approaches zero.

Worked example. Take the AAA/BBB/junk company from above, where the model assigned p^AAA≈0.659\hat{p}_{AAA} \approx 0.659p^​AAA​≈0.659, p^BBB≈0.242\hat{p}_{BBB} \approx 0.242p^​BBB​≈0.242, p^junk≈0.099\hat{p}_{junk} \approx 0.099p^​junk​≈0.099. ℓ(i)=−[1⋅log⁡(0.659)+0⋅log⁡(0.242)+0⋅log⁡(0.099)]=−log⁡(0.659)≈0.417\ell^{(i)} = -\Big[1 \cdot \log(0.659) + 0 \cdot \log(0.242) + 0 \cdot \log(0.099)\Big] = -\log(0.659) \approx \mathbf{0.417}ℓ(i)=−[1⋅log(0.659)+0⋅log(0.242)+0⋅log(0.099)]=−log(0.659)≈0.417

ℓ(i)=−log⁡(0.099)≈2.313\ell^{(i)} = -\log(0.099) \approx \mathbf{2.313}ℓ(i)=−log(0.099)≈2.313

This is structurally identical to the binary gradient derived earlier, predicted probability minus actual label, times the input feature, averaged over examples. Softmax regression is really CCC copies of that same update rule running in parallel, one per class, coupled only through the shared normalization in the denominator of the softmax function itself.

Evaluating a Classifier: Why Accuracy Alone Can Lie

Evaluating a classifier is trickier than evaluating a regression model. The simplest metric, accuracy, is the share of predictions the model gets right. It is also frequently misleading.

Suppose only 5 percent of loans in a dataset actually default. A model that always predicts no default, ignoring every input feature entirely, will still be right 95 percent of the time. That 95 percent accuracy number describes a useless model. This exact trap shows up in market direction models too. A logistic regression that predicts market direction with 72 percent accuracy sounds impressive, until you notice the market simply rises about 72 percent of the time in the sample, and the model may just be predicting “up” nearly every time.

The Confusion Matrix

A confusion matrix breaks predictions down by actual and predicted class, rather than collapsing everything into one accuracy number.

Predicted Negative Predicted Positive
Actual Negative True Negative False Positive
Actual Positive False Negative True Positive

A perfect classifier has nonzero values only on the diagonal, every true negative correctly called negative, every true positive correctly called positive.

Precision and Recall

Precision=TPTP+FP,Recall=TPTP+FN\text{Precision} = \frac{TP}{TP + FP}, \qquad \text{Recall} = \frac{TP}{TP + FN}Precision=TP+FPTP​,Recall=TP+FNTP​

Breaking this down. Precision asks, of everything the model flagged as positive, how much was actually positive. Recall asks, of everything that was actually positive, how much did the model catch. TP, FP, and FN are true positives, false positives, and false negatives, the raw counts from the confusion matrix above.

F1=2×Precision×RecallPrecision+RecallF_1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}F1​=2×Precision+RecallPrecision×Recall​

The F1 score blends precision and recall into one number, and rewards a classifier that keeps both reasonably high, rather than one that maximizes only one of them.

What this means in practice. At threshold 0.5, the model catches 85.7 percent of actual defaults, recall, but three out of nine flagged loans, roughly a third, are false alarms. Neither threshold is universally correct. A lender worried about missing defaults would tolerate more false alarms and choose the lower threshold. The F1 score confirms this trade-off numerically, dropping from 0.750 to 0.444 as precision is bought at recall’s expense.

Precision and recall move in opposite directions as the threshold changes, which is exactly why a single accuracy number cannot describe this trade-off. The Receiver Operating Characteristic curve, ROC, plots the true positive rate against the false positive rate across every possible threshold.

It also captures something the single threshold-0.5 metrics could not. Conclusion: From Probabilities to Decisions

Logistic regression turns a raw, unbounded score into a probability, using the sigmoid function, and trains that probability using log loss rather than squared error. Softmax regression extends the same idea to any number of categories, guaranteeing the resulting probabilities sum to one. Neither model should be judged on accuracy alone. A confusion matrix, precision, recall, and the ROC curve tell you what kind of mistakes a classifier is actually making, which matters more than a single headline number whenever the two classes are not equally common.

The same regularization ideas from the previous article carry over directly here. A logistic regression with too many correlated features overfits in exactly the same way a linear regression does, and Ridge or Lasso penalties fix it the same way.

So far, every model in this series has assumed a straight-line, or straight-boundary, relationship between features and the outcome. Real financial relationships are frequently not linear at all. The next article in this series moves to models built specifically to handle that: Naive Bayes and Decision Trees for Financial Classification.
